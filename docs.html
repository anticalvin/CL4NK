HOW CL4NK
FITS TOGETHER.

The website is headquarters. It is not the brain. CL4NK is being designed so the companion, identity and memory can live on the user's machine.

Architecture

Desktop shell

The actual companion interface. Planned around Tauri so the application can stay small and cross-platform.

Inference adapter

A replaceable boundary for local runtimes such as Ollama and llama.cpp-compatible servers. The identity should not depend on one model vendor.

Memory

SQLite for living local state. Portable JSON bundles for backup and migration. The user remains able to inspect, edit and delete remembered information.

Identity

CL4NK's identity is treated as configuration and behavior rather than something buried inside a hosted account. Personality, memory policy, runtime preferences and tool permissions should be portable independently from model weights.

Permission model

Tools that can touch files, execute commands, use the network or access other resources should be explicit and revocable. A funny robot is not an excuse for invisible authority.

[DESIGN RULE] personality ≠ model
[DESIGN RULE] memory belongs to user
[DESIGN RULE] hosted services remain optional
[DESIGN RULE] dangerous tools require permission
